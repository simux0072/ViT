Understanding Vision Transformers

A conceptual guide to ViT architecture, model names, implementation decisions, common difficulties, and a practical testing strategy.

Overview Model names Architecture Implementation Challenges Testing I-JEPA

1. What is a Vision Transformer?

A Vision Transformer, or ViT, represents an image as a sequence of small patches and processes that sequence with a Transformer.

Transformers were originally designed for sequences of words. ViT adapts the same idea to images: an image is divided into patches, each patch becomes a token, and self-attention allows every patch to exchange information with every other patch.

Image → Patches → Tokens → Transformer → Output

Unlike a convolution, self-attention is not inherently restricted to a local neighborhood. A patch in the upper-left corner can directly attend to a patch in the lower-right corner in a single layer.

2. Reading ViT model names

A name such as ViT-L/16 has two important components. The letter describes the model's approximate capacity, while the number describes the patch size.

ViT-B/16

Base-sized Transformer using 16 by 16 pixel image patches.

ViT-L/16

Large Transformer using 16 by 16 pixel image patches.

ViT-H/14

Huge Transformer using 14 by 14 pixel image patches.

Important: these are conventions, not strict laws. Architecture details can vary between papers and libraries. The architecture table in the relevant paper is the authoritative source.

Calculating the number of tokens

For an image with height H, width W, and square patch size P, the number of patch tokens is:

number of patches = (H / P) × (W / P)

A 224 by 224 image with 16 by 16 patches produces a 14 by 14 grid, which is 196 patch tokens. A classification model may add one class token, producing a sequence of 197 tokens.

Smaller patches preserve finer details but create longer sequences. Standard attention grows approximately with the square of sequence length, so patch size strongly affects memory and compute costs.

3. The components of a ViT

Patch extraction

Divide the image into non-overlapping square regions. For a patch size of 16, each patch contains 16 × 16 pixels across all input channels.

Patch projection

Flatten each patch and project it into the model's embedding dimension. In practice, this is commonly implemented as a convolution whose kernel size and stride both equal the patch size.

Position embeddings

Self-attention alone does not know where a token came from. Position embeddings are therefore added to patch tokens so the model can distinguish top from bottom and left from right.

Optional class token

For classification, a learned class token is commonly inserted at the start of the sequence. Its final representation is passed to a classification head. Other systems may pool all patch tokens instead.

Transformer encoder blocks

A standard ViT block contains two major operations:

  1. Multi-head self-attention, which allows tokens to exchange information.
  2. A feed-forward network, usually containing two linear layers and a nonlinear activation such as GELU.

Layer normalization and residual connections surround these operations. Modern ViTs usually use pre-normalization: tokens are normalized before attention and before the feed-forward network.

Output head

The final representation can feed a classifier, decoder, detection head, segmentation head, projection network, or self-supervised prediction system. The appropriate head depends on the task.

4. A general implementation plan

  1. Choose the supported image and patch sizes. Begin with fixed-size square images whose dimensions are divisible by the patch size.
  2. Implement patch projection. Convert an input batch shaped like batch, channels, height, width into a sequence shaped like batch, tokens, embedding width.
  3. Add special and positional tokens. Optionally prepend a class token and add one position embedding to every token.
  4. Build one encoder block. Use pre-layer normalization, multi-head attention, a residual connection, another normalization, an MLP, and another residual connection.
  5. Stack multiple blocks. Make the number of blocks, embedding width, head count, and MLP width configurable.
  6. Add final normalization and a task head. For classification, normalize the output and pass the class token or pooled patch representation to a linear classifier.
  7. Initialize and train carefully. Use an optimizer such as AdamW. Common recipes include learning rate warmup, cosine decay, weight decay, stochastic depth, and strong image augmentation.
  8. Add advanced features only after the basic model works. Possible additions include variable resolutions, relative positions, masked tokens, efficient attention, or self-supervised objectives.

5. Difficult implementation points

Tensor shapes

Attention libraries may expect different dimension orders. Write down every expected shape and assert it during development.

Head dimensions

The embedding width must normally be divisible by the number of attention heads.

Position interpolation

A model pretrained at one resolution needs its grid of learned position embeddings resized before use at another resolution. The class-token position must be handled separately.

Memory use

Attention matrices grow quadratically with token count. High resolution and small patches can exhaust memory quickly.

Training stability

Initialization, normalization, learning rate, warmup, weight decay, and augmentation can have a large effect on results.

Limited data

Plain ViTs have fewer built-in image assumptions than CNNs and may require strong regularization, pretraining, or more data.

6. How to test an implementation

Unit tests

  • Verify the number of patches for several valid image sizes.
  • Verify that patch projection produces the expected token shape.
  • Confirm that adding a class token increases sequence length by one.
  • Confirm that each encoder block preserves the sequence shape.
  • Test that invalid image and patch-size combinations fail clearly.
  • Test positional-embedding interpolation independently.
  • Confirm that gradients reach patch projection and early blocks.

Behavioral tests

  • Try to overfit a very small dataset. Failure usually indicates an implementation, optimization, or data-pipeline problem.
  • Check that the loss decreases on a simple synthetic task.
  • Compare parameter counts with a known reference configuration.
  • Ensure dropout and stochastic depth behave differently in training and evaluation modes.
  • Save and reload the model, then verify identical evaluation output.

Performance tests

  • Measure peak memory at different image and patch sizes.
  • Measure training throughput and inference latency.
  • Check for accidental copies or unnecessary tensor reshaping.
  • Compare outputs with a trusted library when using matching weights.
The most useful early test is often to overfit a tiny dataset. A correctly implemented model should be capable of nearly memorizing a handful of examples.

7. How this relates to I-JEPA

I-JEPA uses a Vision Transformer as an encoder, but changes the learning objective. Instead of predicting image pixels, the model predicts abstract target representations for hidden image regions using information from visible context regions.

A simplified I-JEPA system contains:

  • A context encoder that processes visible image patches.
  • A target encoder that produces representations to predict.
  • A predictor that estimates hidden-region representations from the visible context and positional information.
  • A masking strategy that selects context and target image regions.
  • A slow-moving update mechanism for the target encoder, commonly based on an exponential moving average.

Thus, a label such as ViT-H/14 still describes the backbone: a Huge ViT using 14 by 14 patches. The term I-JEPA describes the self-supervised training method applied to that backbone.

8. Mental model

Think of a ViT as a pipeline that changes an image from a spatial array into a token sequence:

  1. Split the image into patches.
  2. Project each patch into an embedding.
  3. Add information about patch position.
  4. Mix information globally using self-attention.
  5. Transform each token using an MLP.
  6. Repeat the process through many encoder blocks.
  7. Use the resulting representations for a downstream objective.

The model-size letter controls capacity. The number after the slash controls patch granularity. The training method determines what representations the architecture learns.
